# ProcuraIQ — Database Schema

**Version:** 0.1 — Hackathon Draft  
**Last Updated:** 2026-08-22  
**Status:** Draft — Sufficient for Supabase implementation

---

## 1. Overview

Database: PostgreSQL (hosted on Supabase)

All UUIDs are generated by PostgreSQL (`gen_random_uuid()`).  
All timestamps use `TIMESTAMPTZ` in UTC.  
No ORM — queries use the Supabase client or raw SQL via `psycopg2`.

---

## 2. Entity Summary

| Table | Description |
|---|---|
| `vendors` | Vendor master data |
| `vendor_performance` | Aggregated historical performance per vendor per category |
| `vendor_transactions` | Individual historical transaction records |
| `procurement_requests` | User-submitted procurement requirements |
| `procurement_decisions` | Final decisions produced by the system |
| `financial_exposures` | Calculated Money At Risk per decision |

## 3. Table Definitions

---

### 3.1 `vendors`

Stores vendor master data.

```sql
CREATE TABLE vendors (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            TEXT NOT NULL,
    code            TEXT UNIQUE NOT NULL,        -- Short internal code e.g. "VENDOR_001"
    categories      TEXT[] NOT NULL,             -- Array of procurement categories this vendor serves
    active          BOOLEAN NOT NULL DEFAULT TRUE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_vendors_categories ON vendors USING GIN (categories);
CREATE INDEX idx_vendors_active ON vendors (active);
```

**Fields:**

| Column | Type | Nullable | Description |
|---|---|---|---|
| `id` | UUID | NOT NULL | Primary key |
| `name` | TEXT | NOT NULL | Full vendor name |
| `code` | TEXT | NOT NULL | Unique short code |
| `categories` | TEXT[] | NOT NULL | Procurement categories served |
| `active` | BOOLEAN | NOT NULL | Whether vendor is currently active |
| `created_at` | TIMESTAMPTZ | NOT NULL | Record creation time |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Record last updated |

---

### 3.2 `vendor_performance`

Aggregated performance metrics per vendor per category. This is what the ML model and scoring engine primarily read.

```sql
CREATE TABLE vendor_performance (
    id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    vendor_id                   UUID NOT NULL REFERENCES vendors(id) ON DELETE CASCADE,
    category                    TEXT NOT NULL,
    transaction_count           INTEGER NOT NULL DEFAULT 0,
    on_time_delivery_rate       NUMERIC(5,4) NOT NULL,   -- 0.0000 to 1.0000
    avg_quality_score           NUMERIC(5,4) NOT NULL,   -- 0.0000 to 1.0000
    defect_rate                 NUMERIC(5,4) NOT NULL,   -- 0.0000 to 1.0000
    avg_lead_time_days          NUMERIC(6,2) NOT NULL,
    lead_time_stddev_days       NUMERIC(6,2) NOT NULL DEFAULT 0,
    avg_unit_price              NUMERIC(12,2),
    avg_payment_terms_days      INTEGER,
    avg_advance_payment_pct     NUMERIC(5,4),            -- 0.0000 to 1.0000
    price_stddev_pct            NUMERIC(5,4),            -- Price volatility as fraction
    last_updated                TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(vendor_id, category)
);

CREATE INDEX idx_vperf_vendor ON vendor_performance (vendor_id);
CREATE INDEX idx_vperf_category ON vendor_performance (category);
```

**Fields:**

| Column | Type | Description |
|---|---|---|
| `vendor_id` | UUID FK | References `vendors.id` |
| `category` | TEXT | Procurement category |
| `transaction_count` | INTEGER | Number of historical orders |
| `on_time_delivery_rate` | NUMERIC(5,4) | Historical on-time delivery % |
| `avg_quality_score` | NUMERIC(5,4) | Average quality score |
| `defect_rate` | NUMERIC(5,4) | Historical defect/rejection rate |
| `avg_lead_time_days` | NUMERIC(6,2) | Average actual lead time |
| `lead_time_stddev_days` | NUMERIC(6,2) | Lead time variability |
| `avg_unit_price` | NUMERIC(12,2) | Average price per unit |
| `avg_payment_terms_days` | INTEGER | Average payment terms |
| `avg_advance_payment_pct` | NUMERIC(5,4) | Average advance payment fraction |
| `price_stddev_pct` | NUMERIC(5,4) | Price volatility fraction |

### 3.3 `vendor_transactions`

Individual historical procurement transactions. Source of truth for model training data.

```sql
CREATE TABLE vendor_transactions (
    id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    vendor_id               UUID NOT NULL REFERENCES vendors(id) ON DELETE CASCADE,
    category                TEXT NOT NULL,
    transaction_date        DATE NOT NULL,
    quantity                INTEGER NOT NULL,
    unit_price              NUMERIC(12,2) NOT NULL,
    total_order_value       NUMERIC(14,2) NOT NULL,       -- quantity × unit_price
    promised_lead_time_days INTEGER NOT NULL,
    actual_lead_time_days   INTEGER,                      -- NULL if not yet delivered
    quality_score           NUMERIC(5,4),                 -- 0 to 1, NULL if not yet assessed
    defect_quantity         INTEGER NOT NULL DEFAULT 0,
    payment_terms_days      INTEGER NOT NULL,
    advance_payment_pct     NUMERIC(5,4) NOT NULL DEFAULT 0,
    order_complexity        NUMERIC(5,4) NOT NULL DEFAULT 0.5,  -- 0 to 1 derived score
    outcome                 SMALLINT,                     -- 1=success, 0=failure, NULL=pending
    created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_vtrans_vendor ON vendor_transactions (vendor_id);
CREATE INDEX idx_vtrans_category ON vendor_transactions (category);
CREATE INDEX idx_vtrans_date ON vendor_transactions (transaction_date);
CREATE INDEX idx_vtrans_outcome ON vendor_transactions (outcome) WHERE outcome IS NOT NULL;
```

**Fields:**

| Column | Type | Description |
|---|---|---|
| `vendor_id` | UUID FK | References `vendors.id` |
| `category` | TEXT | Procurement category |
| `transaction_date` | DATE | Order date |
| `quantity` | INTEGER | Units ordered |
| `unit_price` | NUMERIC(12,2) | Price per unit |
| `total_order_value` | NUMERIC(14,2) | Total value of order |
| `promised_lead_time_days` | INTEGER | Agreed delivery lead time |
| `actual_lead_time_days` | INTEGER | Actual time to delivery (NULL if pending) |
| `quality_score` | NUMERIC(5,4) | Quality assessment score |
| `defect_quantity` | INTEGER | Units rejected/defective |
| `payment_terms_days` | INTEGER | Payment terms (e.g., 30, 60) |
| `advance_payment_pct` | NUMERIC(5,4) | Fraction of order paid in advance |
| `order_complexity` | NUMERIC(5,4) | Derived complexity score (0–1) |
| `outcome` | SMALLINT | 1=successful, 0=failed, NULL=pending |

### 3.4 `procurement_requests`

User-submitted procurement requirements.

```sql
CREATE TABLE procurement_requests (
    id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    category                TEXT NOT NULL,
    quantity                INTEGER NOT NULL,
    required_lead_time_days INTEGER NOT NULL,
    budget_per_unit         NUMERIC(12,2) NOT NULL,
    min_quality_score       NUMERIC(5,4),
    weight_delivery         NUMERIC(5,4) NOT NULL DEFAULT 0.35,
    weight_quality          NUMERIC(5,4) NOT NULL DEFAULT 0.25,
    weight_price            NUMERIC(5,4) NOT NULL DEFAULT 0.20,
    weight_lead_time        NUMERIC(5,4) NOT NULL DEFAULT 0.10,
    weight_payment          NUMERIC(5,4) NOT NULL DEFAULT 0.10,
    status                  TEXT NOT NULL DEFAULT 'pending',  -- pending, completed, cancelled
    created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT weights_sum CHECK (
        ABS((weight_delivery + weight_quality + weight_price + weight_lead_time + weight_payment) - 1.0) < 0.001
    )
);

CREATE INDEX idx_preq_status ON procurement_requests (status);
CREATE INDEX idx_preq_category ON procurement_requests (category);
CREATE INDEX idx_preq_created ON procurement_requests (created_at DESC);
```

**Fields:**

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Primary key |
| `category` | TEXT | Procurement category |
| `quantity` | INTEGER | Units required |
| `required_lead_time_days` | INTEGER | Maximum acceptable lead time |
| `budget_per_unit` | NUMERIC(12,2) | Target maximum price per unit |
| `min_quality_score` | NUMERIC(5,4) | Minimum quality threshold |
| `weight_*` | NUMERIC(5,4) | Scoring weights (must sum to 1.0) |
| `status` | TEXT | Request lifecycle status |

### 3.5 `procurement_decisions`

Final decision output for each procurement request, storing all factors that contributed to the decision.

```sql
CREATE TABLE procurement_decisions (
    id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    procurement_request_id      UUID NOT NULL REFERENCES procurement_requests(id),
    recommended_vendor_id       UUID NOT NULL REFERENCES vendors(id),
    alternative_vendor_id       UUID REFERENCES vendors(id),
    composite_score             NUMERIC(5,4) NOT NULL,
    ml_predicted_outcome        SMALLINT NOT NULL,           -- 1 or 0
    ml_confidence               NUMERIC(5,4) NOT NULL,
    risk_level                  TEXT NOT NULL,               -- Low / Medium / High
    supplier_health_score       NUMERIC(5,4) NOT NULL,
    decision_rationale          JSONB NOT NULL,              -- Structured rationale
    confidence_level            TEXT NOT NULL,               -- High / Medium / Low
    created_at                  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_pdec_request ON procurement_decisions (procurement_request_id);
CREATE INDEX idx_pdec_vendor ON procurement_decisions (recommended_vendor_id);
CREATE INDEX idx_pdec_created ON procurement_decisions (created_at DESC);
```

**Fields:**

| Column | Type | Description |
|---|---|---|
| `procurement_request_id` | UUID FK | References `procurement_requests.id` |
| `recommended_vendor_id` | UUID FK | Recommended vendor |
| `alternative_vendor_id` | UUID FK | Alternative vendor (nullable) |
| `composite_score` | NUMERIC(5,4) | Business composite score of recommended vendor |
| `ml_predicted_outcome` | SMALLINT | ML model prediction (1/0) |
| `ml_confidence` | NUMERIC(5,4) | ML prediction confidence |
| `risk_level` | TEXT | Overall risk level |
| `supplier_health_score` | NUMERIC(5,4) | Supplier health aggregate |
| `decision_rationale` | JSONB | Structured rationale object |
| `confidence_level` | TEXT | High / Medium / Low |

**`decision_rationale` JSONB structure:**

```json
{
  "top_factors": ["string", ...],
  "score_breakdown": { "delivery": 0.82, "quality": 0.78, ... },
  "risk_flags": ["string", ...],
  "why_not": { "vendor_id": "reason_string", ... }
}
```

### 3.6 `financial_exposures`

Calculated Money At Risk figures linked to a procurement decision.

```sql
CREATE TABLE financial_exposures (
    id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    procurement_decision_id     UUID NOT NULL REFERENCES procurement_decisions(id),
    purchase_value              NUMERIC(14,2) NOT NULL,
    price_risk_exposure         NUMERIC(14,2) NOT NULL DEFAULT 0,
    supplier_risk_exposure      NUMERIC(14,2) NOT NULL DEFAULT 0,
    payment_risk_exposure       NUMERIC(14,2) NOT NULL DEFAULT 0,
    delivery_risk_exposure      NUMERIC(14,2) NOT NULL DEFAULT 0,
    quality_risk_exposure       NUMERIC(14,2) NOT NULL DEFAULT 0,
    total_money_at_risk         NUMERIC(14,2) NOT NULL,
    protection_actions          JSONB,                       -- List of recommended actions
    post_protection_exposure    NUMERIC(14,2),
    money_protected             NUMERIC(14,2),
    calculation_inputs          JSONB NOT NULL,              -- All inputs used — for auditability
    created_at                  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_fexp_decision ON financial_exposures (procurement_decision_id);
```

**Fields:**

| Column | Type | Description |
|---|---|---|
| `procurement_decision_id` | UUID FK | References `procurement_decisions.id` |
| `purchase_value` | NUMERIC(14,2) | Total order value |
| `price_risk_exposure` | NUMERIC(14,2) | Calculated price risk in currency |
| `supplier_risk_exposure` | NUMERIC(14,2) | Calculated supplier risk |
| `payment_risk_exposure` | NUMERIC(14,2) | Calculated payment/advance risk |
| `delivery_risk_exposure` | NUMERIC(14,2) | Calculated delivery risk |
| `quality_risk_exposure` | NUMERIC(14,2) | Calculated quality risk |
| `total_money_at_risk` | NUMERIC(14,2) | Sum of all risk exposures |
| `protection_actions` | JSONB | Recommended actions and expected impact |
| `post_protection_exposure` | NUMERIC(14,2) | Exposure after actions applied |
| `money_protected` | NUMERIC(14,2) | Reduction in exposure from actions |
| `calculation_inputs` | JSONB | Full audit trail of inputs used |

**`protection_actions` JSONB structure:**

```json
[
  {
    "action": "Request delivery penalty clause",
    "risk_type": "delivery",
    "expected_exposure_reduction": 12000.00
  }
]
```

## 5. Data Constraints Summary

| Rule | Enforced By |
|---|---|
| Weight columns must sum to 1.0 (±0.001) | CHECK constraint on `procurement_requests` |
| Vendor-category performance uniqueness | UNIQUE constraint on `vendor_performance` |
| Vendor code uniqueness | UNIQUE constraint on `vendors.code` |
| Cascade delete on vendor removal | ON DELETE CASCADE on `vendor_performance`, `vendor_transactions` |
| All numeric scores: 0.0000–1.0000 | Application-level validation (NOT DB constraint for MVP) |

---

## 6. Index Strategy

Indexes are provided for all foreign keys and common filter columns.  
GIN index on `vendors.categories` for array-contains queries.  
DESC index on created_at columns for recency-first queries.
